# Aladin AI - End-to-End Architecture

## Overview
Aladin AI is a premium, state-of-the-art conversational AI platform. It utilizes a containerized microservices architecture to provide a seamless chat experience, agent customization, multi-modal interactions (vision, documents), and universal LLM integrations (via OpenRouter and others).

The system is highly modular, separating concerns into a rich client interface, a robust core API, a specialized RAG engine, a unified LLM proxy, and specialized data stores for full-text search, relational/vector data, and NoSQL documents.

---

## 1. Core Services

### Frontend (Client)
- **Stack**: React, Vite, Tailwind CSS, Playwright (for E2E tests).
- **Location**: `/client`
- **Role**: Delivers a sleek, glassmorphic dark-themed UI. Handles user interactions, chat rendering, agent building, and file uploads.

### Backend (Core API)
- **Stack**: Node.js, Express, Mongoose.
- **Location**: `/api` (with shared models/schemas in `/packages`)
- **Role**: The central nervous system. Manages user authentication, multi-user accounts, agent logic, permissions, and request routing to other internal services (RAG, Search, LLMs).

### RAG API (Retrieval-Augmented Generation)
- **Stack**: Python.
- **Location**: `/aladin-rag-api`
- **Role**: Specializes in document parsing, embedding generation, and semantic search. It connects directly with the Vector DB to provide context to the LLM for chat-with-document capabilities.

### LiteLLM Proxy
- **Stack**: Docker image (`ghcr.io/berriai/litellm`).
- **Role**: Standardizes LLM API calls. It sits between the Aladin API and external providers (OpenRouter, OpenAI, Anthropic, Google), managing routing, fallbacks, and keys securely.

---

## 2. Data Persistence & Search

### MongoDB
- **Role**: Primary database.
- **Usage**: Stores user accounts, chat threads, agent configurations, server settings, and application states.

### PostgreSQL (with pgvector)
- **Role**: Vector database.
- **Usage**: Stores document embeddings generated by the RAG API. It enables extremely fast similarity searches to retrieve relevant context when users chat with their PDFs or documents.

### Meilisearch
- **Role**: Full-text search engine.
- **Usage**: Indexes chat histories and user data to provide instantaneous, typo-tolerant search functionality within the UI.

---

## 3. Infrastructure & Deployment

### Container Orchestration
- **Docker & Docker Compose**: The entire stack is spun up using `docker-compose.yml`, which networks the `api`, `mongodb`, `meilisearch`, `vectordb`, `litellm`, and `rag_api` services securely via internal Docker networks.
- **Multi-Stage Builds**: `Dockerfile.multi` is used for efficient backend builds.

### CI/CD Pipelines
- **GitHub Actions**: 
  - `dev` branch: Triggers automated testing (including Playwright E2E testing).
  - `prod` branch: Builds and publishes Docker images to the GitHub Container Registry.

### Configuration Management
- Environment variables (`.env`) and dedicated YAML configs (`aladin.yaml`) are used to securely inject API keys (e.g., `MEILI_MASTER_KEY`, `LITELLM_MASTER_KEY`, `POSTGRES_PASSWORD`) and app settings without embedding secrets in the codebase.
